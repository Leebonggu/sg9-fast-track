# 전자동의 명부 임포트 (업체 → 우리)

서울시 전자동의 시스템에서 내려받은 「전자동의서 대상자관리」 xlsx **2종이 한 쌍**이다
(신속통합기획 + 정비계획입안, 같은 날 내려받은 것). 하나만 받으면 진행하지 말고 나머지를 요청하라.

## 절차 (순서 엄수 — 모든 명령은 `web/`에서)

1. **검증 (읽기 전용, 필수)**
   ```
   npm run verify-econsent -- <신속통합.xlsx> <정비계획입안.xlsx>
   ```
   - 세대 수가 2,830인지, 경고가 기지 패턴(추진방식 소유자 간 불일치, 잘린 연락처)뿐인지 확인
   - "알려지지 않은 값" 경고가 나오면 **중단** — 판정 규칙(econsent-parser.ts)부터 손봐야 한다
2. **백업**: `npm run backup-now`
3. **업로드 확정** — 둘 중 하나:
   - 웹 UI `/unified/econsent-import` (미리보기로 diff 확인 후 확정)
   - 서버 없이: `commitEconsentUpload(sintoBuf, planBuf, '업로더이름')` 호출 스크립트를
     `web/scripts/`에 임시 생성해 `npx tsx --env-file=.env.local`로 실행, 끝나면 삭제
     (scratchpad에 두면 ESM이 node_modules를 못 찾아 실패한다)
   - 「전자동의원본」 overwrite + 「전자동의변경로그」에 diff 기록. 통합현황엔 아직 반영 안 됨
4. **동기화**: `npm run sync-now` — 통합현황 2,830행 재작성 (전자동의 6컬럼은 파생값)

## 완료 기준

- sync 출력이 `2830행`이고 중복 세대 0건
- 변경로그에 배치 요약 1행 + 변경 행들이 기록됨

## 함정

- 두 파일이 뒤바뀌거나 회차가 다르면 파서가 throw한다 (`선택 항목` 컬럼·행별 동/호/이름 대조)
- 원본 xlsx는 절대 수정하지 않는다 — 읽기만
- 파일은 개인정보다. repo에 커밋 금지, Downloads에 그대로 둔다
