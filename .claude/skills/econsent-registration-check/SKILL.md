# 서면동의 등록 결과 확인 → 공유 명단 → 마감

역동기화 사이클의 마지막 단계다: econsent-writeback으로 만든 파일을 사람이 업체에
일괄 등록한 뒤, 재다운로드 파일로 결과를 검증하고 정방향 임포트로 루프를 닫는다.

```
[econsent-writeback] → 사람이 업체 등록 → [이 스킬] 검증·공유명단 → [econsent-import] 마감
```

## 절차 (`web/`에서)

1. **검증 + 공유 명단** (읽기 전용):
   ```
   npm run verify-registration -- <재다운로드.xlsx> <등록전원본.xlsx> [명단.md]
   ```
   - 명단 md 생략 시 docs/raw에서 모드(신통/입안)에 맞는 최신 역동기화 명단을 자동 선택
   - 기대 결과: **표기 전원 `서면동의(직접)` + `자동완비`**, 제출일시 동일, 드리프트 0건
   - 공유용 동별 명단이 출력된다 — 사용자에게 그대로 전달 (개인정보 — repo에 저장 금지)
2. **정방향 임포트로 마감**: econsent-import 스킬 절차 그대로
   (verify-econsent → backup-now → 확정 → sync-now).
   **반드시 같은 시각에 내려받은 신통·입안 쌍**이어야 한다 — 한쪽만 새로 받았으면
   나머지도 재다운로드를 요청하라.
3. **기록**: 최종 숫자(서면 행 수, 완전 세대 수 변화)를 docs/MEMORY.md 해당 절에 갱신

## 함정

- **recipientSeq로 행을 대조하지 마라** — 무명 행 39개가 실소유자 행의 seq를 공유해서
  중복 키 오매칭으로 "명부가 대량 변경됐다"는 허상이 보인다 (2026-08-22 실제로 겪음).
  verify-registration은 동-호+이름으로만 대조한다.
- 드리프트가 진짜로 있으면(새 전자동의 유입 등) 임포트 때 변경로그에 잡히는 게 정상 —
  등록 실패가 아니라 명부가 산 것. 다만 우리 표기 행의 상태가 틀리면 등록 실패이니 중단.
- 검증 실패(✗) 상태로 공유 명단을 내보내지 마라 — 스크립트가 exit 1로 막는다.
