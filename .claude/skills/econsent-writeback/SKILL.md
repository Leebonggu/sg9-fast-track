# 서면동의 역방향 동기화 (우리 → 업체)

업체 벌크등록 흐름: **내려받기 → 엑셀 수정 → 업로드·비교 → 일괄 등록**.
우리는 2단계(엑셀 수정)를 자동화한다. 업체 사이트 업로드는 사람이 한다.
신통·정비계획입안 두 파일 모두 지원 — 모드는 헤더로 자동 감지(`선택 항목` 컬럼 있으면 입안).

## 실행 (`web/`에서)

```
npm run econsent-writeback -- <업체파일.xlsx> [--include=동-호,…] [--exclude=동-호,…]
```

- 원본 옆에 `_서면동의반영.xlsx` 사본 생성 (원본 불변)
- 명단 리포트: `docs/raw/YYYY-MM-DD_서면동의_역동기화_명단[_입안].md` (개인정보 — 커밋 금지)
- **`--exclude=905-1008,910-605` 항상 지정** — 신분증만 있고 동의 없음, 2026-08-22 사용자 확정 제외

## 대상·규칙 (스크립트가 자동 적용)

- 대상 세대: 통합현황 **종이 동의(신통=consent / 입안=planConsent) + 신분증 제출**(업로드>0 또는 종이수령)
  — "신분증까지 제출된 대상만 입력"이 사용자 확정 기준
- 바꾸는 건 `제출상태` 한 컬럼뿐: `미제출`/`철회` → `서면동의(직접)`
- 사람 고르기: 단독=그 행 / 공유=동의서 서명자·신분증 제출자와 이름 매칭되는 행만
- 이름 불일치 단독 세대는 **보류** → 사람이 판단 후 `--include=동-호`로 포함
  (포함해도 리포트 '이름 확인 필요'에 남는다. 통합현황 메모에도 기록해줄 것)
  — 916-1506(최영희/최명희)은 사용자가 포함 결정한 선례

## 실행 후 반드시 검증

원본 vs 출력 파일을 셀 단위 diff 해서 **변경 셀 수 = 스크립트가 보고한 행 수,
변경 컬럼 = 제출상태 하나뿐**임을 확인하고 사용자에게 숫자를 보고한다.

## 업체 사이트에서 사람이 할 일 (안내해줄 것)

1. 대상자 일괄 등록에 `_서면동의반영.xlsx` 업로드
2. 비교 화면의 변경 건수가 우리 숫자와 일치하는지 확인 (다르면 등록 중단)
3. 등록 화면에서 제출일시 입력 (실제 수거일은 v2 동별 시트 '수거일' 컬럼 참고)

등록이 끝나면 **econsent-registration-check 스킬**로 이어진다
(재다운로드 검증 → 공유 명단 → 정방향 임포트 마감).

## 함정

- 업체 룰: 이미 제출(전자/서면)된 행은 변경 불가, 숨김 컬럼(recipientSeq 등)·열 구성 유지 필수
- `완비여부`·`신분증` 컬럼은 건드리지 않는다 — 서면동의 등록만 하면 업체가 '자동완비' 처리
  (2026-08-22 실측: 신통 39행 전원 자동완비. 업체는 신분증을 아예 수집 안 함 — 증빙은 우리 시트가 원천)
- 입안 파일의 `선택 항목`(추진위/직접조합)은 벌크로 입력 불가 — 서면동의 행은 '-'로 남는다
  (업체가 8/3 수동 등록한 908-107도 '-' + 자동완비). 선택값이 법적으로 필요하면 업체에 문의
- xlsx 재인코딩으로 서식은 빠질 수 있음(값·열 구성은 보존) — 업체가 거부하면 exceljs 전환 검토
- 등록이 끝나면 다음 정방향 임포트(econsent-import)에서 서면동의(직접)로 내려와 자동으로 아귀가 맞는다
