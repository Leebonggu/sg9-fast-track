# 통합현황 안전 동기화

sync는 통합현황 2,830행을 **전체 재작성**하는 파괴적 연산이다. 2026-08-13에 쿼터(429)로
시트가 통째로 빈 사고가 있었다(이후 values.update 1회 쓰기 + batchGet으로 수정됨).

## 절차 (`web/`에서)

1. `npm run backup-now` — 실행 전 백업 (매일 KST 01:00 cron 백업과 별개의 즉시 백업)
2. `npm run sync-now`
3. 출력 확인: `동기화 완료: 2830행`이어야 정상. 행 수가 다르거나 중복 세대가 나오면 보고

## 언제 필요한가

- sync 로직/설문 config/전자동의 판정 등 **코드 변경 후** (CLAUDE.md 규칙: 변경 후 1회 필수)
- 전자동의 명부 임포트 후 (econsent-import 스킬 4단계)
- 단, **표시 로직만 바꾼 경우**(컴포넌트·필터·인쇄)는 시트에 쓰는 값이 없으므로 불필요

## 복구 (통합현황이 비었을 때)

- 백업 스프레드시트는 `BACKUP_FOLDER_ID` Drive 폴더에 `통합현황백업_YYYY-MM-DD`로 30일 보관
- 위원 수기 입력 컬럼(메모·연령대·단톡방·정비입안 3종·연락처_수정 등)은 sync가 보존하는
  값이라, 시트가 빈 상태에서 sync를 또 돌리면 **보존값이 사라진다** — 반드시 백업 복원 먼저
