# 신분증 사본 업로드 재개 설계

## 배경

신분증 사본 업로드 시스템은 2026-06-07 커밋(`9294b22`)으로 구축·배포됐으나, 2026-06-22 커밋(`f39d9fb` "신분증 관련 UI 전체 숨기기")으로 UI 진입점이 전부 제거되어 현재(2026-07-12)까지 실질적으로 정지된 상태다. 데이터(Drive 파일, `신분증업로드` 시트 기록)와 API 라우트, Apps Script 모드는 보존되어 있다.

재개 논의 중 핵심 우려가 제기됐다: 기존 인증 방식(동/호수/이름 일치)은 이미 `/check-submission`에서 신통기획·설문 완료여부 열람에 쓰이고 있는데, 이 정보가 단톡방 등을 통해 제3자에게 알려질 경우 신분증이라는 더 민감한 자원까지 같은 약한 인증으로 접근·변조될 수 있다는 점이다. 이 설계는 그 위험을 "최초 1회 제출 후 즉시 잠금" + "정정은 관리자 확인을 거친 온디맨드 1회용 링크로만" 구조로 완화한다.

## 목표

- 신속통합동의서(신통기획) 제출 완료 세대(`row.consent === true`)의 소유자로부터 (1) 개인정보 수집·이용 동의, (2) 신분증 사본, (3) 전화번호를 받는다.
- 기존 `/check-submission/result` 페이지 안에서 신통기획/설문 진행 상황 확인과 같은 화면 흐름으로 업로드까지 처리한다(설계 시작 시점 요구사항 유지).
- 동/호/이름이라는 약한 인증 하나로 반복 변조가 가능한 상태를 없앤다: 최초 제출은 허용하되, 그 이후 수정은 관리자 확인 없이는 불가능하게 잠근다.
- 개인정보 수집·이용 동의를 "화면상 체크로 업로드 버튼이 활성화되는 것"에서 "언제 동의했는지 시트에 단독으로 남는 기록"으로 바꾼다.

## 범위 밖

- 실물 종이 서명본 수집 워크플로우 (나중에 필요해지면 별도 설계 — 지금은 컬럼도 만들지 않음)
- `getPhoneMap`의 "소유주아님" 번호 미필터링 버그 수정 (별개 이슈, `project_phone_notowner_exclusion.md` 참고)
- 신분증업로드 전화번호 → 통합현황 `연락처` 자동 병합 (여지만 남겨두고 구현하지 않음)

## 아키텍처

### 최초 제출 (기존 흐름 유지)

1. 주민이 `/check-submission`에서 동/호/이름 입력 → 기존 `getOwnersByDongHo` 대조 → HMAC 토큰 발급(30분, `kakao-verify.ts`) — **변경 없음**
2. `/check-submission/result?t=token`에서 `row.consent === true`인 경우에만 `IdUploadSection` 노출 — 기존과 동일
3. 소유자 슬롯별로 신분증 사진 + 전화번호를 함께 입력 후 제출
4. `POST /api/upload-id`가 처리:
   - rate limit / 동의여부 / 소유자 대조는 기존 로직 그대로
   - **신규**: 해당 (동, 호, ownerIndex) 슬롯에 이미 활성 레코드가 있고 `정정허용시각`이 비어 있으면 403으로 거부 ("이미 제출된 슬롯입니다. 수정이 필요하면 위원에게 문의해주세요")
   - 업로드 성공 시 `개인정보동의시각`(요청 시각), `전화번호`를 함께 기록하고, 만약 이 요청이 `정정허용` 상태를 통해 열린 것이었다면 성공 직후 `정정허용시각`을 비워 재잠금

### 정정 (오프라인 요청 → 관리자 발급 1회용 링크)

새 토큰 체계를 만들지 않는다. 기존 HMAC 토큰 + 시트의 `정정허용시각` 플래그 하나로 구현한다.

1. 주민이 위원에게 전화/카톡으로 정정 필요성을 알린다 (사진은 이 채널로 절대 주고받지 않는다 — 카톡 자체가 더 큰 유출 경로이므로, 요청 사실만 전달)
2. 위원이 통화로 신원을 확인한다 (기존 `동의서수거` 등 다른 수기 확인 프로세스와 동일 선상의 인적 신뢰 경계)
3. 위원이 `/unified` 관리자 패널(`IdUploadAdmin`, pw 게이트)에서 해당 세대·소유자 슬롯의 "정정 허용" 버튼 클릭
   → 서버가 `신분증업로드` 시트의 그 행에 `정정허용시각 = now`를 기록 (유효 2시간)
   → 화면에 기존 주민용 결과 페이지로 가는 1회용 링크(토큰은 원래 방식대로 동/호만 인코딩된 표준 HMAC 토큰 재사용, 새로 발급)를 표시
4. 위원이 그 링크만 카톡으로 전달
5. 주민이 링크로 접속 → `정정허용시각`이 유효하므로 재촬영 버튼이 노출됨 → 재업로드
6. 업로드 성공과 동시에 `정정허용시각` 클리어 → 즉시 재잠금. 링크를 다시 눌러도 서버가 플래그 없음을 보고 거부하므로 별도의 "링크 1회 사용 이력" 관리가 필요 없다.
7. 2시간 경과 후에도 사용되지 않으면 서버가 만료 처리 (재업로드 시도 시 일반 잠금과 동일하게 거부) — 위원이 다시 "정정 허용"을 눌러야 함

## 데이터 모델 변경

`신분증업로드` 시트(기존 컬럼: 시각/동/호수/소유자명/소유자순번/파일명/파일ID/Drive링크/IP/상태)에 3개 컬럼 추가:

| 컬럼 | 설명 |
|---|---|
| `개인정보동의시각` | 업로드 성공 시점의 ISO 타임스탬프. 파일 유무와 무관하게 "언제 동의했는지" 단독 증명 |
| `전화번호` | 업로드 시 소유자 본인이 입력. 통합현황 `연락처`와는 별개로 보관하며 서로 자동 반영하지 않음 |
| `정정허용시각` | 관리자가 "정정 허용" 클릭 시 세팅. 빈 값이면 잠금 상태, 값이 있고 2시간 이내면 재업로드 허용 |

`id-upload.ts`에 `getIdUploadPhone(dong, ho, ownerIndex)` 형태의 조회 함수를 별도로 둔다 — 지금은 어디서도 호출하지 않지만, 나중에 "신분증업로드 번호로 통합현황 연락처 갱신" 같은 병합 액션을 추가할 때 `owner-sheets.ts`를 건드리지 않고 이 함수만 불러 쓸 수 있게 하기 위함.

## UI 변경

**주민 (`IdUploadSection.tsx`, 복원 + 수정)**
- 슬롯별 촬영/선택 UI에 전화번호 입력 필드 추가, 사진과 함께 한 번에 제출
- 제출 완료 슬롯: "제출완료 · 수정은 위원에게 문의" 고정 표시로 교체, 재촬영 버튼 제거
- `정정허용` 상태인 슬롯만 예외적으로 재촬영 버튼 노출

**관리자**
- `EditRowModal`에 `IdUploadAdmin` 복원: 열람(프록시 썸네일)·폐기 + 전화번호 표시 + 슬롯별 "정정 허용" 버튼(클릭 시 1회용 링크 생성·표시)
- `UnifiedSummary`: 신분증 제출 통계 카드 복원 (죽어있던 `idDoneCount` 계산 재사용)
- `UnifiedFilters`: '신분증 미제출' 필터 버튼 복원
- `/unified/id-print`: 변경 없음 (이미 동작 중)

## 기존 데이터 처리 (2026-06-07~06-22 제출분)

- 이미 제출된 건은 재제출을 요구하지 않고 그대로 "제출완료"로 인정한다
- `개인정보동의시각`·`전화번호`는 그 시점 데이터가 없으므로 공란으로 남긴다 (실제로 언제 동의했는지 모르는 상태에서 임의로 소급 기록하면 오히려 증거로서의 신뢰가 깨짐)

## 에러 처리 / 엣지 케이스

- **잠긴 슬롯 재요청**: `POST /api/upload-id` → 403 "이미 제출된 슬롯입니다"
- **정정허용 만료**: 2시간 경과 후 재업로드 시도 시 일반 잠금과 동일하게 거부
- **전화번호 형식**: 클라이언트+서버 양쪽에서 숫자·하이픈 위주로 느슨하게 검증 (엄격한 정규식으로 제출 실패를 늘리지 않는다)
- **rate limit / IP 로그**: 기존 `kakao-verify-log.ts` 그대로 재사용, 변경 없음
- **공동소유 추가 슬롯(+10)**: 기존 로직 유지, 정정 허용도 슬롯 단위이므로 추가 슬롯에도 동일 적용
