## 설계 원칙

### 원칙 1 — 임포터는 통합현황 시트에 쓰지 않는다

덮어쓰기 금지를 규칙이 아니라 구조로 보장한다.

```
[위원] xlsx 2개 업로드
   ↓
파싱·정규화 (상가 제외, 동-호수-이름 검증)
   ↓
「전자동의원본」 시트 overwrite      ← 임포터의 쓰기 권한은 여기까지
   ↓
syncMasterSheet() 가 읽어 세대 단위 집계
   ↓
통합현황 신규 컬럼 (매 sync 재계산되는 파생값)
```

raw 시트를 경유하는 이유:

1. 통합현황이 순수 파생 뷰로 남는다. 임포터가 원장에 접근할 경로 자체가 없다.
2. 세대당 여러 필드(대표자·소유자수·선택항목·제출일)를 자유롭게 뽑을 수 있다.
3. 판정 규칙(△ 처리 등)이 바뀌어도 **재업로드 없이 sync만 다시** 돌리면 된다.

### 원칙 2 — 종이 기록은 어떤 경로로도 임포터가 건드리지 않는다

절대 쓰지 않는 컬럼:

| 컬럼 | 이유 |
|---|---|
| `신속통합동의서_제출_완료` | sync가 v2에서 매번 계산해 overwrite. 양방향 소실 위험. |
| `정비계획입안_동의서` | 위원이 오프라인 수령 후 손으로 체크. 엑셀에 없다는 이유로 지워짐. |
| `개인정보수집동의` | 〃 |
| `신분증_수령` | 〃 |
| `연령대` | 위원 수정분과 설문 시드가 섞여 있어 구분 불가. |

### 원칙 3 — 읽기 실패는 throw

`getMasterPreservation`과 동일하게, 전자동의 시트 읽기 실패를 silent catch하면 다음 sync가 전자동의 값을 전부 빈칸으로 덮는다. 반드시 throw해서 sync가 `writeMasterRows`에 도달하지 못하게 한다.

## 구현

### 1. 「전자동의원본」 시트 (신규, 소유자 단위 3,181행)

두 파일을 한 시트로 병합. 소유자 1명 = 1행.

```
동 | 호수 | 연번 | 이름 | 생년월일 | 연락처 | 소유구분 | 대표자여부
  | 신통_제출상태 | 신통_제출일시 | 입안_제출상태 | 입안_제출일시
  | 입안_선택항목 | 업로드일시
```

- 병합 키: 행 인덱스 + `동-호수-이름` 검증. 검증 실패 시 임포트 전체 거부.
- 상가(`건물명`에 `상가` 포함 또는 `동`이 비어있는 행)는 제외.
- 모든 셀 `sanitizeCell` 적용.

### 2. 통합현황 신규 컬럼 6개 (세대 단위 파생)

| 컬럼 | 값 |
|---|---|
| `신속통합_전자동의` | `완전` / `일부` / 빈칸 |
| `정비계획입안_전자동의` | `완전` / `일부` / 빈칸 |
| `공유_소유자수` | 2~5 (단독은 빈칸) |
| `공유_대표자` | 대표자 이름, 미선임이면 빈칸 |
| `추진방식_선택` | `추진위원회 구성` / `직접조합설립` |
| `연령대_명부` | 생년월일 파생 구간값 |

`연령대_명부`를 별도 컬럼으로 두는 이유는 원칙 2와 같다. 표시할 때 `연령대 || 연령대_명부`로 합치면 비어 있던 세대는 채워지고 위원 입력은 남는다. 값이 충돌하는 세대는 리포트로 뽑아 사람이 판단한다.

**생년월일 원본은 통합현황에 저장하지 않는다.** raw 시트에만 두고 구간값만 올린다.

### 3. 연락처 우선순위

```
위원수정(연락처_수정) > v2 동의서 > 전자동의 명부 > 설문 응답
```

명부는 소유자 본인 명부라 "소유주아님" 번호가 섞일 여지가 없어 설문 응답보다 위에 둔다. `연락처`는 이미 sync가 계산하는 파생값이라 별도 컬럼이 필요 없다.

### 4. 세대 단위 판정 규칙

```
제출한 소유자 수 = 0            → 빈칸 (미제출)
제출한 소유자 수 = 전체 소유자 수 → "완전"
그 외                          → "일부"
```

제출 판정: `제출상태`가 빈 문자열도 `미제출`도 아닌 경우(`전자동의`, `서면동의(직접)`).

### 5. 파생 표시 규칙 (시트 컬럼 없음, `unified-utils.ts`)

```
신속통합 종합    = 종이(신속통합동의서_제출_완료) OR 전자(완전)
정비계획입안 종합 = 종이(정비계획입안_동의서) OR 전자(완전)
신분증 인정      = 종이수령 OR 온라인업로드 OR 전자동의제출
개인정보 인정     = 종이체크 OR 전자동의제출
```

아래 두 줄이 §원본 데이터 실측의 운영 판단을 구현한 것이다. 판단이 바뀌면 이 두 줄만 고치면 되고 원장은 손상되지 않는다.

### 6. 전이 이력 — 「전자동의변경로그」 시트 (신규)

raw 시트에 직전 업로드 스냅샷이 남아 있으므로, overwrite 직전에 diff를 떠서 무엇이 바뀌었는지 기록한다.

기존 `변경로그` 시트에는 **붙이지 않는다.** 그 시트는 위원이 모달에서 원본 4필드를 손으로 고친 이력 전용이고, 필드당 1행씩 쌓인다. 첫 업로드 926행이 쏟아지면 사람이 고친 기록이 묻힌다. 후원금이 `후원금변경로그`를 따로 쓰는 것과 같은 선례를 따른다.

```
시각 | 동 | 호수 | 이름 | 필드 | 이전값 | 새값 | 업로드배치 | 업로더
```

추적 대상 6개:

| 필드 | 잡히는 것 |
|---|---|
| `신통_제출상태` | 미제출 → 전자동의 (신규 동의) |
| `입안_제출상태` | 〃 |
| `입안_선택항목` | 추진위 구성 ↔ 직접조합설립 (입장 변경) |
| `대표자여부` | 미선임 → 대표/위임 (대표 선임 성사) |
| `소유자명단` | 소유권 이전 |
| `연락처` | 번호 갱신 |

`소유자명단`은 소유자 행이 아니라 **세대 단위 이름 집합**으로 비교한다. 공유자가 늘거나 줄면 행이 사라져 행 단위로는 "삭제+추가"로 보이기 때문이다. 세대로 묶어야 `901-503 [류지민] → [강민규, 김채리]` 한 줄로 읽힌다.

두 가지 규칙:

- **첫 업로드는 요약 1행만** 남긴다. 비교 대상이 없어 전부를 "변경"으로 기록하면 로그가 baseline 노이즈로 시작한다.
- **변경 0건이어도 배치 요약 1행은 항상** 남긴다(`필드 = (업로드)`). 언제 누가 어떤 파일을 올렸는지가 감사 가능해야 하고, 같은 파일 중복 업로드도 여기서 드러난다.

`업로드배치`는 업로드 시각 기반 ID로, 한 번의 업로드로 생긴 변경이 한 덩어리로 묶인다.

`owner-sheets.ts:279`의 `logChanges`가 이미 원하는 모양이므로 시트명을 파라미터로 빼서 재사용한다. 헤더 자동 보강 로직도 딸려온다.

- 확정 후: 이번 배치 변경 내역 표시
- 상단에 뒤로가기 + 관련 페이지 링크 (관리자 서브페이지 네비게이션 규칙)

**통합현황 표** — 항목당 1컬럼 `〇/△/X` + 출처 배지(`종이` / `전자` / `종이·전자`).

**집계 카드** — 합산 큰 숫자 + 경로별 내역.

```
┌─ 신속통합 동의 ────────┐  ┌─ 정비계획입안 동의 ─────┐
│    1,109 세대  39.2%    │  │      410 세대  14.5%    │
│ 종이 1,022 · 전자 506    │  │ 종이 20 · 전자 390       │
│ (중복 419)              │  │ (일부제출 30 별도)       │
└────────────────────────┘  └────────────────────────┘
```

**신규 필터** — `△ 일부만 제출`, `대표 미선임`, `추진방식별`.

### 8. 리포트 2종 (읽기 전용, 원본 미수정)

두 리포트 모두 별도 페이지가 아니라 **통합현황 필터**로 제공한다. 기존 `대표 미선임`·`반대 의사`와 같은 방식이라 위원이 새 화면을 익힐 필요가 없고, 필터 결과에 기존 엑셀 내보내기가 그대로 걸린다.

- `소유권 이전 의심` (`roster-name-mismatch`) — 70세대. 표에 `명부 [이름]` 배지가 붙어 원본과 나란히 보인다.
- `공유 대표 미선임` (`no-representative`) — 259세대. 그중 32세대는 이미 일부가 서명해 대표만 세우면 완결되므로 독려 우선순위 1번(`공유자 일부만 서명` 필터).

원본 시트를 직접 고치지 않고 목록만 제공한다. 판단은 사람이 한다.

## 검증 기준

1. 파서가 2026-08-10 파일 2개에서 아파트 3,181행 / 2,830세대를 뽑고 상가 45행을 스킵한다.
2. 세대 판정이 신통 〇474/△32, 입안 〇390/△30과 일치한다.
3. 대표 선임 75 / 미선임 259, 추진위 구성 441 / 직접조합설립 40이 재현된다.
4. 임포트 후 sync 1회 실행 시 기존 컬럼(메모·재건축반대·단톡방참여·정비계획입안_동의서·개인정보수집동의·신분증_수령·연락처_수정·연령대)이 임포트 전과 완전히 동일하다. **이게 가장 중요한 회귀 검증이다.**
5. 같은 파일을 두 번 업로드하면 변경 0건 + 배치 요약 1행만 남는다.
6. 두 번째 업로드에서 값이 바뀐 세대만 전이 로그에 남는다.
7. 병합 후 집계가 신속통합 1,109세대(39.2%) / 정비계획입안 410세대와 일치한다. 종이 쪽은 라이브 시트 기준이라 배포 시점에 재측정한다.
8. 파생 규칙 적용 후 개인정보 인정·신분증 인정이 각각 400세대 이상으로 증가한다.

## 배포 순서

1. 코드 배포
